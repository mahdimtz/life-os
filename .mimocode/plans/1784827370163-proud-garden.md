## فاز 0: تغییرات دیتابیس

### فایل: `prisma/schema.prisma`

**Task model** — اضافه کردن `goalId`:
```prisma
model Task {
  // ... existing fields ...
  goalId String?    // NEW: ارتباط با هدف
  @@index([goalId])
}
```

**Settings model** — اضافه کردن تنظیمات باشگاه:
```prisma
model Settings {
  // ... existing fields ...
  gymDays  String @default("[]")   // NEW: JSON array از شماره روزهای هفته [0-6]
  gymPlan  String @default("[]")   // NEW: JSON array از تمرینات
}
```

**Migration**: `npx prisma migrate dev --name add-goal-link-gym-config`
- SQLite: اضافه کردن ستون → کاملاً backward-compatible با دیتای موجود

### فایل: `src/types/index.ts`
- اضافه کردن `goalId?: string` به interface Task
- اضافه کردن `gymDays?: number[]` و `gymPlan?: string[]` به interface Settings

## فاز 1: آپدیت API

### 1A. تسک + هدف

**`src/app/api/tasks/route.ts`** (POST)
- قبول کردن `goalId` اختیاری در body → ذخیره در دیتابیس

**`src/app/api/tasks/[id]/toggle/route.ts`** (PATCH)
- بعد از toggle: اگه تسک `goalId` داره و کامل شده:
  - شمارش کل تسک‌های مرتبط با اون هدف
  - شمارش تسک‌های تکمیل شده
  - محاسبه progress = `(completed / total) * 100`
  - آپدیت goal.progress

**`src/lib/api.ts`**
- آپدیت `tasksApi.create` → قبول `goalId?: string`

### 1B. یادگیری → آپدیت DailyStats

**`src/app/api/learning/route.ts`** (POST)
- بعد از ساخت entry: upsert DailyStat برای اون تاریخ
- محاسبه مجموع ساعات یادگیری → `studyHours`

### 1C. ژورنال → آپدیت DailyStats

**`src/app/api/journal/route.ts`** (POST)
- بعد از ساخت entry: upsert DailyStat برای اون تاریخ
- تنظیم `mood` و `journalWritten = true`

### 1D. باشگاه (جدید)

**`src/app/api/gym/toggle/route.ts`** (NEW)
- `POST /api/gym/toggle` با `{ date: string }`
- Upsert DailyStat → toggle `gymSession`

**`src/lib/api.ts`**
- اضافه کردن `gymApi: { toggle: (date?) => ... }`

## تصمیمات طراحی

| تصمیم | دلیل | جایگزین رد شده |
|-------|-------|---------------|
| برنامه فردا = تسک با تاریخ فردا | ساده‌ترین راه، بدون مدل جدید | مدل جداگانه "Plan" → پیچیدگی اضافی |
| تنظیمات باشگاه در Settings (JSON) | الگوی موجود identityValues | مدل جدید GymConfig → overkill |
| پیشرفت هدف در API محاسبه میشه | جلوگیری از ناهمگامی دیتا | محاسبه سمت کlient → ریسک drift |
| Notification با setInterval | ساده‌ترین راه کارآمد | Service Worker push → پیچیدگی زیاد |
| mood = عدد (5-1) برای نمودار | امکان نمودار خطی | نمودار میله‌ای → کمتر قابل فهم |
